# Sprint 4 — P1 (Backend & Data Modeling) - davesarti

## What I built:
This sprint the big deliverable on my side was the **session evaluation endpoint** — the B-family judge calls plus the A-family deterministic metrics, persisted and cached on the backend so the UI can render the eval modal without paying four LLM calls every time. Alongside that I promoted **datasets to a first-class DB entity**, picked up the **A4 Mahalanobis OOD** metric that P2 had open on its generalization eval, refactored the engine's turn-apply path into a single **TurnBuilder** stage, and shipped a batch of UI, prompt, and docs fixes across the rest of the system.

- **Session evaluation endpoint** (`backend/routers/sessions.py`, `src/engine/f_eval.py`, `src/eval_report.py`): added `GET /sessions/{id}/eval` that runs the four LLM judges — overall (B1), coherence (B2), compliance (B3), contradiction (B4) — and the deterministic A1/A2/A3 metrics on the current snapshot, then persists the result on the session row so eval results survive process restarts and DB reloads. Split the inline eval prompt into four dedicated prompts (`prompts/f_eval_coherence.txt`, `_compliance.txt`, `_contradiction.txt`, `_overall.txt`) so each judge has a tight contract. Deleted `src/engine/f_next_state.py` and its tests — the function was unused after the eval split. The UI now fetches the full eval bundle from the endpoint instead of running anything client-side.

- **Eval cache** (`backend/eval_cache.py`, `src/models.py` `EvalCache` table): added a content-hash cache keyed by SHA256 over the exact judge payloads (clusters, feedback history, compliance turns, coherence samples) **plus prompt-file hashes and the model name**, so any change to the snapshot, the prompts, or the harness model invalidates the entry automatically. This is what makes the eval modal feel free on a re-open while still being correct after a turn lands or a prompt is edited.

- **Cognitive load extracted to its own module** (`src/engine/f_cognitive_load.py`, `src/engine/cognitive_load_caps.py`, `tests/test_f_cognitive_load.py`): pulled cognitive-load handling out of `harness.py` into a dedicated engine function with its own caps table and 168 lines of tests. Cleans up the harness (now ~87 lines lighter) and makes the cap policy auditable in one file.

- **Datasets as a first-class DB entity** (`src/models.py`, `backend/routers/datasets.py`, `src/dataset_processing/`, with P2): added the `datasets` table and `dataset_id` FKs across `sessions`, `clusters`, `turns`, and `data_points`; updated the seed/load pipeline (`seed_data.py`, `dataset_load_utils.py`, `verify_database.py`) so every dataset row carries an explicit identity and description. Co-designed with P2 — the migration is non-destructive (no embeddings touched), and all 30+ test files that touched the old "data" model were updated in the same commit so the suite stayed green.

- **Datasets API + welcome label** (`backend/routers/datasets.py`, `ui/index.html`, `tests/test_datasets_endpoint.py`, issue #51): `GET /datasets` now returns `n_points` and `has_embeddings` per dataset via a single GROUP BY query (no per-row N+1), and the welcome page label adapts to the available datasets (e.g. "Amazon (1200 points, ready)" vs "20NG (no embeddings yet)"). Closed #51.

- **Re-embedding op at every turn** (`backend/routers/turns.py`, `prompts/f_output.txt`, `tests/test_turns_semantic_reembed_op.py`): the previous flow only allowed `semantic_reembed` at turn 1 (initial clustering). Extended the turns router so `semantic_reembed` can be emitted at any turn — the snapshot is dissolved and rebuilt under the new axis, with the boundary repair and naming pipeline running on the new clusters. Updated `f_output.txt`'s decision tree so the LLM knows it's a legal mid-conversation op, and added a 139-line test file covering the all-turns case.

- **TurnBuilder refactor** (`src/engine/turn_builder.py`, `backend/routers/turns.py`, `src/engine/cluster_operations.py`, `src/engine/f_apply_operations.py`): the conversational-turn path was previously a tangle of inline snapshot mutations split across `turns.py`, `f_apply_operations.py`, and several helpers in `cluster_operations.py` — every op type wrote its own snapshot row independently, which made boundary-repair and eval ordering fragile. Introduced `TurnBuilder` that stages all the clustering effects of a single turn (merge/split/move/rename/reembed/boundary repair) and commits them as **one snapshot per turn**. Net change: +1011 / −1133 lines across the engine + tests, suite still green.

- **Generalization GMM-posterior + A4 Mahalanobis OOD** (`src/engine/generalization.py`, `scripts/run_generalization_stability_eval.py`, `tests/test_generalization.py`, issue #71): picked up the A4 distance-based OOD metric P2 had open — implemented Mahalanobis distance against the parent cluster's posterior covariance, with a chi-squared cutoff for the OOD threshold, and wired it into the stability eval alongside A1/B2. Replaced the nearest-centroid assignment with a proper GMM-posterior assignment so the OOD rate is consistent with how the clusters were actually fit. 383 lines on the engine, 444 on the tests (mostly numerical fixtures).

- **Auto-name on bare rename + 5-sample naming floor** (`src/engine/cluster_naming.py`, `src/engine/cluster_operations.py`, `prompts/f_output.txt`, `src/engine/f_apply_operations.py`): two related fixes. (1) When the oracle emits a `rename` without a target name (e.g. "rename this one to whatever makes sense"), the engine now calls `name_clusters` on the affected cluster instead of failing — same path used after a split/reembed. (2) Set a 5-sample floor for naming: clusters with fewer than 5 hard members are tagged with a placeholder name and re-named once they grow, preventing the LLM from picking a name off a single data point that happens to be an outlier.

- **Placeholder-cluster retry after fuzzy-match miss** (`src/engine/cluster_naming.py`): `name_clusters` matches the LLM's returned UUIDs back to clusters with a fuzzy match (the model occasionally returns a truncated or mistyped UUID). When the fuzzy match missed, the cluster was left with a placeholder name forever. Added a second pass that re-asks the LLM specifically for the unmatched clusters, with their full UUIDs spelled out — recovers most of the misses.

- **LLM-as-oracle CLI + persona system** (`scripts/run_persona_eval.py`, `src/eval/llm_oracle.py`, `src/eval/oracle_view.py`, `src/eval/persona.py`, `personas/*.json`, `prompts/llm_oracle.txt`): added a CLI runner that drives a full clustering session as an LLM oracle — loads a persona JSON (dataset, k, temperament, satisfaction criterion), opens a session against the backend, and runs turns until the oracle reports satisfied (or hits a max-turns cap). Renamed the old `run_eval.py` → `run_scenario_eval.py` and moved eval modules under `src/eval/`. 17 persona files in `personas/` cover the eval matrix (curious explorer, brisk executive, boundary pedant, prompt injector, typo chaos, bilingual drifter, etc.).

- **Autonomous converged mark on oracle request** (`backend/routers/turns.py`, `src/engine/f_next_best_step.py`, `tests/test_turns_endpoint.py`): when the oracle says "I'm satisfied" / "this is good", the backend now marks the session `converged` autonomously instead of waiting for an explicit PATCH from the UI. Tightened the next-best-step prompt and added 57 lines of tests for the new branch.

- **`batch_move_points` engine op** (`src/engine/cluster_operations.py`, `src/engine/f_apply_operations.py`, `prompts/f_output.txt`, `tests/test_cluster_operations.py`): the UI's "pin a handful of points and move them to cluster X" gesture (and the equivalent oracle utterance) used to round-trip as N separate `move_points` ops, each with its own snapshot mutation. Added a single `batch_move_points` op type that takes a list of `(point_id, target_cluster_id)` pairs and writes one snapshot row. Renormalisation on the source clusters happens once at the end.

- **Pinned-points UI + persona modal** (`frontend/src/components/modals/ExpandClusterModal.tsx`, `frontend/src/components/ChatPanel.tsx`, `frontend/src/components/modals/PersonaModal.tsx`, `frontend/src/store/AppContext.tsx`): added the pin-and-move gesture in the expanded-cluster modal — pinned points are shown in a pinned tray, then the ChatPanel exposes a "move pinned to…" affordance that emits `batch_move_points`. Added a Persona modal in the workspace so a session can be associated with a persona at creation time (the LLM-oracle CLI and the UI share the same persona definitions).

- **UMAP popup + welcome-page session list + minor UI** (`frontend/src/components/modals/UmapModal.tsx`, `frontend/src/components/WelcomePage.tsx`, `frontend/src/components/WorkspacePage.tsx`, `frontend/src/components/ChatPanel.tsx`, `frontend/src/components/AnalyticsPanel.tsx`, `ui/index.html`): the UMAP modal got proper turn navigation and legend; the welcome page now lists existing sessions per dataset (grouped, with status badges); various font-size, label-wrapping, and copy fixes across the workspace.

- **Harness reorganised into a package** (`src/harness/__init__.py`, `src/harness/harness.py`, `src/harness/harness_claude.py`, `src/harness/harness_openai.py`, `src/harness/harness_openrouter.py`): the four flat `src/harness*.py` files had grown to ~1000 lines combined and were hard to navigate. Moved them into `src/harness/` as a package with a clean `__init__.py` surface; no behaviour change, only imports. Done in two commits (one to add the package, one to delete the flat files and re-point the two consumers — `backend/eval_cache.py` and `src/engine/f_cognitive_load.py`).

- **JSON quote tolerance in LLM responses** (`src/harness.py`, `src/harness_openai.py`, `src/harness_openrouter.py`, `prompts/cluster_naming.txt`, `tests/test_harness_json.py`): the harness's JSON extractor used to bail out the moment a string field had an unescaped quote (frequent in cluster names like `Movies "Action"`). Added a recovery pass that escapes the offending quote and re-parses. 46 lines of regression tests + a tightening of the cluster-naming prompt to discourage the model from emitting them in the first place.

- **Dataset-agnostic naming and reembed prompts** (`prompts/cluster_naming.txt`, `prompts/f_output.txt`, `prompts/parse_clustering_intent.txt`): the prompts had crept toward dataset-specific phrasings ("for Amazon product reviews…") which were hurting transfer to 20NG and IMDB. Stripped the dataset assumptions; the dataset description is now injected from the new `prompts/dataset_description.txt` template only where it's actually needed.

- **Docs** (`docs/api-interface.md`, `docs/data-model.md`, `docs/quality_specs.md`, `README.md`, `AGENTS.md`): added `docs/api-interface.md` (412 lines — full endpoint reference for the frontend team and the LLM-oracle CLI), updated `data-model.md` with the dataset table and the eval-cache table, unified `quality_specs.md` by folding `docs/evaluation-plan.md` into it (and deleted the duplicate), refreshed `README.md` with the persona-CLI usage and the eval endpoint, and updated `AGENTS.md` so the function name matches the engine refactor (`f_uncertainty`).

- **Final experimental report** (`docs/final_experimental_report.md`, `reports/session_evals.json`, `docs/figures/fig{1..6}.png`): a 253-line end-to-end quality report written against the §10 quality spec. Three arms judged on the full A1/A2/A3/B1/B2/B3/B4 vector with bootstrap 95% CIs: (a) **persona** — 63 LLM-driven sessions (21 per dataset across Amazon / IMDB / 20NG, max 15 turns); (b) **real users** — 6 live oracle sessions (2 per dataset); (c) **no-dialogue baseline** — a single-turn "no changes needed" run per dataset, used **only** as the B2 reference. Includes a real-users-vs-persona simulation-gap analysis (B4 contradiction 0.553 vs 0.266 pooled — real users are ~2× harder than the personae). Six figures: B2 vs baseline, persona-quality bars, real-vs-persona pooled, termination breakdown, A1 silhouette, real-user overlay on the persona distributions. `reports/session_evals.json` (808 lines) holds the raw eval payloads for the baseline + user + persona arms the report aggregates from.

- **Generalization stability report** (`docs/generalization-stability-report.md`, `docs/figures/generalization-{a1-forest,a4-ood,b2-forest,b2-shift}.png`, `scripts/generate_generalization_charts.py`): the formal write-up of the §10 robustness dimension on the 6 user sessions — paired Δ A1 silhouette on the 1200 common points, A4 Mahalanobis OOD rate vs the 5 % chi-squared null with Wilson CIs, and paired Δ B2 coherence with bootstrap CIs over the 3–8 per-session clusters. Per-session forest plots + a cohort-level summary (n = 6). Identifies user2/amazon as the only clean failure (A1 −0.0005 [−0.0007, −0.0003] **and** B2 −0.175 [−0.258, −0.083]), user1/newsgroups & user3/imdb as A1-holds-but-A4-elevated cases (8.7 % and 8.0 % OOD with Wilson lower bound > 5 %, the failure mode A4 was added to catch and A1 alone misses), and the cohort-mean OOD at 5.5 % [3.7 %, 7.3 %] — statistically consistent with the null. `generate_generalization_charts.py` (258 lines) reads the per-session logs verbatim, derives the Wilson CIs, and emits the four PNGs; data values are pasted from the logs (no re-aggregation) so the figures stay reproducible from a single source of truth.

- **Generalization eval — clone-an-existing-session mode** (`scripts/run_generalization_stability_eval.py`, +311 / −138): the previous script could only build a *throwaway* converged session from `--base` (initial_clustering + LLM-persona conversation), which meant the generalization eval couldn't be run on the actual real-user sessions sitting in `demo_database.db`. Added a `--session-id` / `--db-url` "Mode B" that opens the real DB, copies the chosen session into an **in-memory clone** (dataset row, ChatSession, every Cluster, every Turn, every DataPoint actually assigned in this session, and every SoftAssignment row for those clusters — full history so A2/A3 eval still works), then runs ingestion + t0/t1 eval against the frozen geometry. The source DB is opened, read, and closed; the +1 snapshot and the `closed` status flip land on the clone and vanish at the end of the run. Resolves the `embedding_model="default"` placeholder real sessions store to the actual `all-MiniLM-L6-v2` name. Mode A (the original `--base` + persona path) is unchanged and still the default. Also bumped B2 sampling from **3 top + 2 bottom** per cluster to **6 top + 4 bottom** (same 3:2 representative-to-edge ratio, 10/cluster instead of 5) — the per-session paired Δ B2 needed a denser signal than the live `/eval` endpoint provides; the divergence is explicitly flagged in the stability report.


## Challenges:
The eval endpoint was a big lift — it touches a lot of code and has to be right because it's the source of truth for the UI's eval modal. The cache design was critical to making it feel responsive while still being correct after any change to the snapshot, prompts, or model. I had to be careful to keep the transaction boundaries clean so the session row is updated atomically with the cache and the eval report.
